Функциональные требования по ролям

Нефункциональные требования
Определяют, насколько хорошо система выполняет свои функции. Любое критическое действие (изменение цены продукта, удаление заказа, изменение статуса оплаты) должно логироваться с указанием пользователя. Система должна разграничивать доступ по ролям: клиент не может получить доступ к страницам сотрудников, кондитер не может изменять цены или просматривать финансовые отчёты, бухгалтер не может редактировать рецепты. Система должна поддерживать добавление новых типов продуктов или новых полей в рецепт без изменения основной логики. По удобству использования интерфейс клиентского сайта должен быть интуитивно понятным, адаптивным (корректно отображаться на десктопах, планшетах и смартфонах), с крупными кнопками для мобильных устройств, формой оформления заказа не более чем из трёх шагов. Интерфейс кондитера должен быть оптимизирован для использования на планшете с крупными элементами и минимальным количеством текста, технологическая карта должна отображаться в виде чек-листа. Интерфейс курьера должен работать в условиях нестабильного интернета, позволяя отмечать статусы офлайн и синхронизировать при восстановлении связи. По совместимости система должна корректно работать на последних версиях браузеров Chrome, Firefox, Safari, Edge, а также на Android и iOS для мобильного приложения курьера. По надежности хранения данных система должна использовать реляционную базу данных с поддержкой транзакций и внешних ключей, обеспечивающую целостность ссылок (невозможно удалить продукт, на который есть ссылки в невыполненных заказах). Система должна иметь механизм автоматического восстановления после сбоя с перезапуском затронутых процессов (например, неотправленные уведомления должны повторяться).
