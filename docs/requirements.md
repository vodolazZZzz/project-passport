## Функциональные требования по ролям
Для роли «Клиент»: система должна позволять регистрироваться по телефону или email, оформлять заказы без регистрации, открывать детальные карточки продуктов, использовать конструктор торта с выбором коржа, начинки, крема, декора, веса, формы и надписи с автоматическим пересчётом цены, добавлять товары в корзину, изменять количество, удалять позиции, выбирать дату и доступный временной слот, указывать адрес доставки или выбирать самовывоз, оплачивать заказ онлайн или при получении, отслеживать статус заказа по временной шкале, просматривать историю заказов в личном кабинете.
Для роли «Менеджер»: система должна позволять просматривать панель с количеством новых, неоплаченных и срочных заказов, работать с таблицей всех заказов с фильтрами по статусу, дате, клиенту и сумме, открывать детали заказа, редактировать состав заказа, изменять дату и время, резервировать слот производства, добавлять служебные комментарии, изменять статус заказа, отменять заказ с указанием причины, просматривать карточку клиента с историей заказов и адресами.
Для роли «Кондитер»: система должна позволять просматривать панель со списком заданий на сегодня, видеть срочные задания и предупреждения о нехватке ингредиентов, просматривать производственный календарь с временными слотами и закреплёнными заказами, открывать детали задания с технологической, отмечать выполнение каждого этапа, создавать заявку кладовщику при нехватке ингредиентов, просматривать свой график работы и количество выполненных заказов.
Для роли «Кладовщик»: система должна позволять просматривать панель с критическими остатками, списком заявок от кондитеров и ожидаемыми поступлениями, работать с таблицей складских остатков, корректировать остатки вручную при инвентаризации, перемещать ингредиенты между складами, осуществлять приёмку товара от поставщика, обрабатывать заявки кондитеров (принять, выдать ингредиент, отклонить с комментарием), создавать заказы поставщикам вручную или по пороговым значениям, отправлять заказ поставщику на email или печатать, проводить инвентаризацию с автоматическим расчётом расхождений и списанием недостачи.
Для роли «Курьер»: система должна позволять видеть панель со списком назначенных доставок на сегодня, просматривать маршрутный лист с карточками заказов, открывать детали доставки (адрес, телефон клиента, желаемый интервал, особые указания), прокладывать маршрут через внешний навигатор, изменять статус доставки («забрано», «в пути», «доставлено», «не доставлено»), указывать причину недоставки.
Для роли «Администратор»: система должна позволять просматривать панель с ключевыми показателями, управлять пользователями, редактировать каталог, управлять рецептами, просматривать финансовые отчёты.
Для роли «Бухгалтер»: система должна позволять просматривать список всех платежей с фильтрацией, инициировать возвраты, формировать ведомость по зарплате.

## Нефункциональные требования
Определяют, насколько хорошо система выполняет свои функции. Любое критическое действие (изменение цены продукта, удаление заказа, изменение статуса оплаты) должно логироваться с указанием пользователя. Система должна разграничивать доступ по ролям: клиент не может получить доступ к страницам сотрудников, кондитер не может изменять цены или просматривать финансовые отчёты, бухгалтер не может редактировать рецепты. Система должна поддерживать добавление новых типов продуктов или новых полей в рецепт без изменения основной логики. По удобству использования интерфейс клиентского сайта должен быть интуитивно понятным, адаптивным (корректно отображаться на десктопах, планшетах и смартфонах), с крупными кнопками для мобильных устройств, формой оформления заказа не более чем из трёх шагов. Интерфейс кондитера должен быть оптимизирован для использования на планшете с крупными элементами и минимальным количеством текста, технологическая карта должна отображаться в виде чек-листа. Интерфейс курьера должен работать в условиях нестабильного интернета, позволяя отмечать статусы офлайн и синхронизировать при восстановлении связи. По совместимости система должна корректно работать на последних версиях браузеров Chrome, Firefox, Safari, Edge, а также на Android и iOS для мобильного приложения курьера. По надежности хранения данных система должна использовать реляционную базу данных с поддержкой транзакций и внешних ключей, обеспечивающую целостность ссылок (невозможно удалить продукт, на который есть ссылки в невыполненных заказах). Система должна иметь механизм автоматического восстановления после сбоя с перезапуском затронутых процессов (например, неотправленные уведомления должны повторяться).
